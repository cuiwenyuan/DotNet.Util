## NewLife.Core/Redis 引用与封装代码 Review（仅列问题，未修复）
### 中危
- **PoolUtil.cs:86** `Pool.MemoryStream.Return(ms)` 归错池：`Pool` 解析为 NewLife.Collections.Pool（NewLife 默认全局池），与 line 29 `PoolUtil.StringBuilder.Return(sb)` 不一致——MemoryStream 应归还 `PoolUtil.MemoryStream`（自定义 64k 上限池），当前自定义池永远收不到对象
- **RedisUtil.cs** `RemoveAll/RemoveByRegex/GetAllKeys` 用 `redisClient.Keys` 全量枚举（KEYS 语义 O(N) 阻塞 Redis，大数据量卡顿）：RemoveAll 建议用 `Clear()`，其余建议 SCAN 分页；且 `RemoveAll` 未判空（`Keys` 可能 null，与 RemoveByRegex 的判空不一致）
- **NewLife 扩展"双份 API"**：DataUtil/SecurityUtil/StringUtil/PathUtil 定义大量 this object/string 扩展，与 NewLife.Core 自带同签名扩展并存——消费者同用 `using NewLife;`+`using DotNet.Util;` 会 CS0121 歧义；`StringUtil.Split(this string, params string[])` 使 `"abc".Split()` 从 .NET 原生（无参抛异常）变为"按逗号分号拆分"，静默语义变化
### 低危
- NewLifeUtil.cs 死代码（MemoryCache/Redis/FullRedis 静态属性全库无使用，且与 MemoryUtil 的 Microsoft.Extensions MemoryCache 同名异类易混淆）
- DbUtil.cs:5 `using NewLife.Log;` 未使用
- SecurityUtil.cs：注释笔误"SHA128"（应为 SHA1）；`MD5(this string, Encoding=null)` 编码依赖 TFM（net462 Default=GBK / net8=UTF-8）跨 TFM 哈希不一致风险，建议显式传 UTF-8；RC4 已破
- RedisUtil.Add/Set 恒返回 true（无法感知写入失败）；Set 的 timeout 注释"0：默认过期时间"与 NewLife 语义（0=不过期）疑似不符
- RedisUtil.GetClient 无配置校验/异常降级（Redis 配置错误时首访抛未捕获异常）
- PathUtil.cs 无用 using（IO.Compression、static MediaTypeNames）
- RedisUtil 非 static class 全静态成员；RandUtil 与 RandomUtil 两套随机工具并存
- 已核实：委托的 NewLife API（Utility/SecurityHelper/Rand/PathHelper/StringHelper）11.18 均稳定、全 TFM 编译通过；DisposeBase 为本地实现非 NewLife 依赖；MemoryUtil 用 Microsoft.Extensions MemoryCache 不在范围
