## 缺陷 1 修复：DbUtil.LockNoWait 静默吞异常（2026-09-18，未提交）

**根因**：`DbHelper.Fill` 内部 catch 异常后把它自己的**局部** `dt` 置 null 并返回
（`DbHelper.Method.cs:677`），调用方传入的 `dt` 不受影响；`LockNoWait` 丢弃 `Fill` 返回值
继续用自己 new 的空表 → 异常静默吞掉、恒返回 0，`catch` 里的 -1 永远不可达。

**改法**（`DbUtil.LockNoWait.cs`）：接收 `Fill` 返回值，`null` → 返回 -1：
```csharp
var filled = dbHelper.Fill(dt, sb.Return(), dbHelper.MakeParameters(parameters));
result = filled == null ? -1 : filled.Rows.Count;
```
两个 `<returns>` XML 注释补"执行失败返回 -1"。
测试 `DbUtilAdvancedIntegrationTests` 两个 LockNoWait 用例恢复名为
`..._ReturnsMinusOneOnSqlServer`，断言由 `Assert.True(result <= 0)` 改为 `Assert.Equal(-1, result)`。

**验证**：net8.0 P5 20/20、Db 命名空间 288/288；net48 P5 19 通过 + 1 跳过；
常规非集成回归 1225（1 失败 = HttpUtilTests 已知 flaky，复跑 8/8）。

**同类模式（未修，已记入 Db-Test-Coverage-Plan.md）**：`SQLBuilder.cs:660`、
`DbUtil.Common.cs:356,377`、`DbUtil.Method.cs:162`、`DbUtil.ParentChildrens.cs:70,112,140,238,291`、
`BaseExceptionManager.Manual.cs:159`、`BaseManager.PreviousNext.cs:53` 共 12 处同样丢弃
`Fill` 返回值。彻底方案是让 `Fill` 异常时抛出或提供 `TryFill`，属行为变更待评估。

## 缺陷 2 定位（net48 宿主崩溃，2026-09-18，未改源码）

**结论：崩的是 `DefaultConvert.ToDecimal` 与 `ToDouble`；`ToInt`、`System.Convert.ToDecimal` 正常。**

对照实验（临时探针 `TempNet48CrashProbe`，已删除）：
- 崩：`ToDecimal`(decimal/string/double/null 输入，5/5)、直调 `global::NewLife.Utility.Convert.ToDecimal`、
  `ToDouble`（**新发现，之前只知 ToDecimal**）
- 正常：空用例、`Convert.ToDecimal`、`ToInt`（int 与 string 输入）
- **打点证据**：`ToDecimal` 前/后/`Sleep(3s)` 后三个标记全部写入、断言通过 → 崩溃发生在
  **用例执行完成后的进程收尾阶段**，返回值本身是正确的。
- net8.0 同路径正常 → .NET Framework runtime 特有。
- 上游源码 `DefaultConvert.ToDecimal/ToDouble` 的 string 分支含 `Span<Char> tmp = stackalloc Char[len]`
  与 `tmp[..rs]`（Range），net4x 依赖 System.Memory 垫片 → 首要嫌疑，定性需 dump。

**影响面（比初判大）**：`.ToDecimal(` 9 处 + `.ToDouble(` 7 处 = **16 处 / 9 文件**。
产品代码 9 处：`RequestUtil.cs`×2、`NewLife/DataUtil.cs`×2、`DbUtil.Aggregate.cs`×1、
`DotNet.Util.Plus/ExcelUtil.Export.cs`×4。
→ **net48 全量回归只要跑到这些用例就会宿主崩溃**，不止 P5 那一例。

**方法论（可复用）**：
1. 进程级崩溃定位 = 临时探针类（每个可疑调用一个 `[Fact]` + 一个空用例对照组）+ filter 逐个跑，
   看哪个把宿主搞崩；跑完立即删探针。
2. 判断"崩在哪个时刻"用**文件打点**（前/后/sleep 后各写一行）比 Console 输出可靠——
   xunit 里 Console 拿不到，文件在崩溃后依然存在。
3. 崩溃时 `dotnet test` 不会自己退出（exit=124 是外部 timeout 杀的），
   所以每次崩溃实验都要套 `timeout 40`，否则 Bash 工具会被拖到超时。
