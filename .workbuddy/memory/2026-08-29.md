### 🔴 P0（数据静默丢失/错乱，3 项）
1. **`CsvUtil.cs:622-623` 赋值顺序颠倒**：`i = j;` 写在 `result -= (j - i);` 之前 → `(j-i)` 恒为 0 → `GetLength` 列数合并完全失效，永远返回 arr.Length。后果：CSV 字段含"引号内分隔符"时，数据行列数 > 表头列数 → `ToDataTable` **整行静默丢弃**（实测 2 行全丢）。修复：交换两行。
2. **`CsvUtil.cs:579` `i = j` 对值参数无效**：`ReadSpecialCharacter(string[] arr, int i, ...)` 里 `i = j` 修改的是局部副本，调用方 `for(j...)` 不受影响 → 已合并片段被重复读取。实测列名出现 `esc"`、数据出现 `world"`、后续列全错位。修复：改 `ref int i` 或返回新索引。
3. **`DateUtil.cs:544-587` GetStartTime/GetEndTime 不处理时分秒**：只做 AddDays/AddMonths，沿用入参时刻。实测入参 `2026-02-15 10:30:45` → start=`02-01 10:30:45`（未归零）、end=`02-28 10:30:45`（未补 23:59:59）。用于 `BETWEEN start AND end` 周期统计会**静默漏首尾数据**。周期日期本身计算正确，问题仅在时分秒。

### 🟠 P1（逻辑/契约，4 项）

## 修复进展 3：Bug 4 IsIpv4 已修（2026-08-29 晚，用户"继续修IsIpv4"）
**改动文件**：`src/DotNet.Util/Util/ValidateUtil.cs`（**先 Read 确认当前内容**；无 BOM、CRLF；新增 `using System.Net;` 与 `using System.Net.Sockets;`）。

方案：改用 `IPAddress.TryParse` + `AddressFamily == InterNetwork` 严格判定 IPv4，**移除原回退到 `IsIpv6` 的逻辑**（方法名即「是否为 IPv4」，回退致语义不符；且 `IsIpv6` 对 `::` 压缩写法判断有误），并加「恰好 3 个点」的严格四段点分校验（避免 .NET 把 `1.2.3` 宽松写法也判成 IPv4，保持与原正则「严格 4 段」语义一致）。`IsIpv4(null)` 现返回 `false`（不再抛 `ArgumentNullException`）。顺手给 `IsIpv6` 补 `null` 判空返回 `false`（原 `ipAddress.Split` 会 NRE）。
